# 八路分拣口参数记录（分拣舵机 A/B 抬升时间）

> 日期：**2026-11-04**　　设备：S-LAN 卡牌自动分拣机
> 来源：现场在「设备连接2 → 测试 → 八路分拣口」逐口调定，已写入硬件并落盘 `Device/config.json`
> 用途：**后续自动化按本表的时间参数执行**，不要再改

---

## 一、参数总表

| 出口 | 单元地址 | A 舵机 | B 舵机 | 固件值 au / bu |
|---|---|---|---|---|
| **1# 左** | 0x20 | **400 ms** | **800 ms** | 40 / 80 |
| **2# 右** | 0x20 | **800 ms** | **400 ms** | 80 / 40 |
| **3# 左** | 0x21 | **500 ms** | **900 ms** | 50 / 90 |
| **4# 右** | 0x21 | **900 ms** | **500 ms** | 90 / 50 |
| **5# 左** | 0x22 | **500 ms** | **900 ms** | 50 / 90 |
| **6# 右** | 0x22 | **900 ms** | **500 ms** | 90 / 50 |
| **7# 左** | 0x23 | **500 ms** | **900 ms** | 50 / 90 |
| **8# 右** | 0x23 | **900 ms** | **500 ms** | 90 / 50 |

**规律：**
- 1#、2# 是单独的一组（400/800 与 800/400）
- 3#~8# 统一：**左口 500/900，右口 900/500**
- 左右口的 A/B 是**互为镜像**的（一个高一个低），靠时间差形成斜面

---

## 二、参数含义（重要）

分拣单元用的是 **360° 连续旋转舵机**，**没有角度概念**，抬升高度由**转动时间**决定：

| 项 | 说明 |
|---|---|
| A / B 单位 | **毫秒**，界面填 ms，固件存 ×10ms（如 400ms → 40） |
| 转得越久 | 抬得越高 |
| A 与 B 差得越大 | 形成的斜面越陡，卡滑得越快 |
| 0 ms | 舵机不转 |
| 上限 | 2550 ms（固件单字节 255 × 10ms） |

**固件默认值**（未调之前的出厂值）：`g_s1_ms = 100`（A 1000ms）、`g_s2_ms = 50`（B 500ms）。

## 三、命令对照（调试或脚本调用用）

### 写参数

```
P,<单元>,au,<A毫秒÷10>      例：P,0x20,au,40    → A 舵机转 400ms
P,<单元>,bu,<B毫秒÷10>      例：P,0x20,bu,80    → B 舵机转 800ms
P,<单元>,spd,<0~100>        转速偏移（×10µs），一般不动
```

**回包：** `[分拣] 参数已设置`

### 动作

```
S,<单元>,raise       两臂按参数抬升（三阶段：抬升 → 保持 → 自动归位）
S,<单元>,lower       两臂下降归位（靠限位开关确认）
S,<单元>,au          只抬 A
S,<单元>,ad          只降 A
S,<单元>,bu          只抬 B
S,<单元>,bd          只降 B
S,<单元>,stop        立即停
S,<单元>,arm         光敏自动触发布防
S,<单元>,disarm      撤防
S,<单元>,selftest    自检
```

**回包：** `[分拣] 0x20,raise OK`

### 读状态

```
T,<单元>            例：T,0x20
回包：0x20,限位=3,有卡=0,阶段=0,抬升=35
```

| 字段 | 含义 |
|---|---|
| 限位 | 3=两臂都在下位；0=两臂都抬起；2/1=有一个抬着 |
| 阶段 | 0=空闲，进行中会变 |
| 抬升 | **累计完成次数，抬升走完一轮 +1（判断有没有真动就看它）** |

## 四、两个出口共用一个单元

**1#/2# 都挂在 0x20 上，3#/4# 挂在 0x21，以此类推。**

单元里只存**一对** A/B 参数，所以：

```
要点「1# 左」→ 必须先写 400/800，再抬升
要点「2# 右」→ 必须先写 800/400，再抬升
```

**⚠️ 硬件不会记住"哪个口"的独立参数，每次切换出口都必须重写参数。**

**这是为什么「抬」按钮会自动先写一遍 A/B 再抬升**（前端已实现：`actOutlet(..., 'raise')` 内部先发两条 `P` 再发 `S`）。**写自动化脚本时也必须遵守同样的顺序，否则会用上一个口的参数。**

---

## 五、配置文件位置

```
Code\V1.3\Device\config.json

"SORT_OUTLETS": [
  {"name":"1#左","addr":"0x20","aMs":400,"bMs":800},
  {"name":"2#右","addr":"0x20","aMs":800,"bMs":400},
  {"name":"3#左","addr":"0x21","aMs":500,"bMs":900},
  ...
],
"SORT_OUTLETS_DATE": "2026-11-04 19:48:03"
```

**后端接口：**

```
POST /outlets/save   {outlets:[{name,addr,aMs,bMs}...]}   → 落盘
GET  /outlets/get                                        → 读回
```

**网页上的「存到配置」按钮就是这个接口。**

## 七、后续自动化的用法

**分拣某个出口时的标准动作序列：**

```
① P,<单元>,au,<A/10>      写 A（覆盖上一次）
② P,<单元>,bu,<B/10>      写 B（覆盖上一次）
③ S,<单元>,raise          抬升
④ 等 1.5~2 秒（抬升 + 保持）
⑤ S,<单元>,lower          归位（或等单元自动归位）
```

**出口 → 单元对照：**

```
1# → 0x20    2# → 0x20
3# → 0x21    4# → 0x21
5# → 0x22    6# → 0x22
7# → 0x23    8# → 0x23
```

**如果之后要改参数：** 改 `config.json` 的 `SORT_OUTLETS`，或直接在网页上改数字点「存到配置」，然后同步到硬件（点各口的「保」或「抬」）。
