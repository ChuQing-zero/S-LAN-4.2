## 一、功能边界

进料模块负责：把料仓里最下面一张卡推出来，推到进料口光敏被遮住为止，然后停电机、计数。

不负责：皮带、挡片、识别、拍照、分拣。这些属于后续模块。

---

## 二、控制链路

```
上位机发 c（推一张）
   ↓
Nano 固件 push_start() 启电机
   ↓
loop() 每圈 push_tick()：读 A7 → 与 g_ldrTh 比较
   ↓
读数 < 阈值 → motor(0,1,0) 停电机 + 计数 +1 + 打印回包
```

**判定与停机全部在 Nano 本地完成，不经过电脑、不依赖 WiFi。** 电脑只发一条 `c`，之后不再参与。

---

## 三、关键参数（当前实机值）

| 参数 | 位置 | 当前值 | 说明 |
|---|---|---|---|
| `g_ldrTh`（推卡阈值） | Nano 固件 RAM | 598（现场由 `q` 下发） | 读数低于此值即停电机 |
| `LDR_THRESHOLDS.A7` | V1.3 config | 598（校准写入） | 页面显示、双张判断用 |
| `CALIB_RATIO_A7` | V1.3 config | 0.77 | 阈值 = 实测亮态 × 0.77 |
| `FEED_BACKOFF_MS` | V1.3 config | 150 | 双张时反转回退时长，0 = 关闭 |
| `FEED_BACKOFF_PWM` | V1.3 config | 120 | 回退转速 |
| `FEED_DOUBLE_WAIT_MS` | V1.3 config | 250 | 推完等多久再查光敏 |

**实测量程（补光灯开）：** 无卡 768~784，有卡 79~87。阈值 598 落在两者之间，余量充足。

**为什么阈值取 600 左右（用户判断）：** 卡刚碰到光敏时读数已经跌到 600 附近，此时停电机，卡靠惯性继续往前走一段，正好到位；若等读数跌到 100（卡压得很正）才停，就推不出去了。

## 四、启动校准（每次「开始运转」执行一次）

```
自检通过 → 灯开、无卡状态下六路各采 3 次取中位数
   ↓
阈值 = 单元亮态 × 0.82（约 2950~3035）
阈值 = A7 亮态 × 0.77（约 598）
   ↓
写回 config.LDR_THRESHOLDS 并落盘
   ↓
下发 q<A7阈值> 给 Nano（q 只写 RAM，断电会回到固件默认 100）
```

日志样例：

```
校准 0x10 亮=3658 ×0.82 → 阈值 2853→3000
校准 A7   亮=777  ×0.77 → 阈值 611→598
已下发进料阈值 q598
```

相关参数：`START_CALIB`（默认 true，可关）、`CALIB_SAMPLES`（3）、`CALIB_GAP_MS`（150）、`CALIB_RATIO_UNIT`（0.82）、`CALIB_RATIO_A7`（0.77）。

## 五、防双张

```
推卡完成（计数 +1）
   ↓
等 FEED_DOUBLE_WAIT_MS(250ms)
   ↓
读 A7
   ├─ ≥ 阈值：进料口已空 → 正常，日志「进料口已空（A7=xxx）」
   └─ < 阈值：判双张 / 卡没走 → 日志「⚠ 可能双张或卡没走」
              → M,R,120,150 反转回退 150ms → M,S 停 → p200 恢复推卡 PWM
```

**注意：`M,R,...` 会把固件 `g_pwm` 改成回退转速，所以回退后必须补发 `p<原PWM>`。**

## 八、冻结约定

1. 进料相关的代码、参数、命令语义**不要再动**。
2. 若后续模块（挡片、识别位、拍照位、分拣口）需要调整阈值，只改对应通道，**不要改 A7 与推卡逻辑**。
3. 断电重启后阈值会回默认 100，靠「开始运转」时的 `q` 下发恢复，**这条链路不要删**。
