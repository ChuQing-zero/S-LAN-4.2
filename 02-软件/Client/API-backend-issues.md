## 一、登录注册接口问题

### 问题 1：注册接口邀请码必填不合理（高优先级）

**现状**：`API-frontend.md` 注册接口要求 `inviteCode` 必填。

**问题**：
- 邀请码机制在早期推广阶段会增加用户注册门槛
- 若后端尚未生成/管理邀请码，前端无法完成注册流程
- 用户体验：需要额外联系管理员获取邀请码，转化率下降

**建议方案**（二选一）：

**方案 A**：后端暂将 `inviteCode` 改为可选
- 前端和后端同步修改，数据库中邀请码字段可为空
- 邀请码有值时记录绑定关系，无值时直接注册成功

**方案 B**：后端提供预置邀请码
- 后端生成若干预置邀请码（如 `LANSRB2026`），在前端注册页面展示
- 用户填入任意一个即可注册，降低获取门槛

**请后端确认**：选择哪个方案？预计何时完成？

### 问题 2：登录/注册响应中缺少 `role` 字段（高优先级）

**现状**：`API-frontend.md` 登录/注册成功响应为：

```json
{
  "token": "...",
  "user": {
    "id": "001",
    "nickname": "小明",
    "email": "user@example.com",
    "avatar": "/static/icons/avatar.png"
  }
}
```

**问题**：
- 首页 `index.vue` 原来使用 `userRole` 显示"管理员"等角色
- 当前响应缺少 `role` 字段，若前端不区分角色可忽略
- 若后续业务需要权限控制（如普通用户 vs 管理员），此字段必须有

**建议**：后端在 `user` 对象中补充 `role` 字段，默认值为 `"user"`。

**请后端确认**：是否补充 `role` 字段？

## 三、识别上传接口问题

### 问题 4：`/vision/recognize` 返回值缺少 `serial` 字段（中优先级）

**现状**：`API-backend.md` 拍照识别成功响应为：

```json
{
  "jpName": "閃刀姫－レイ",
  "cnName": "闪刀姬-零",
  "code": "QCAC-JP059",
  "rarity": "QCSER",
  "confidence": 0.95
}
```

**问题**：
- 前端上传页面需要展示识别结果的序号（`serial`）
- 当前响应无 `serial`，前端上传时需要后端自动生成（已有卡片则用已有序号，新卡生成新序号）
- 建议：识别结果返回时一并返回 `serial`（为空表示新卡，后端入库时再分配）

**建议后端修改**：在识别响应中增加 `serial` 字段，示例：

```json
{
  "jpName": "...",
  "cnName": "...",
  "code": "...",
  "rarity": "...",
  "confidence": 0.95,
  "serial": ""   // 空字符串表示数据库中无此卡，入库时自动分配
}
```
